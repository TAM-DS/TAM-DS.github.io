FEATURED / DEADBOLT · GITHUB MARKETPLACE

Find leaked keys.
Review agent authority.

Catch credential exposure and risky agent configurations before commit or build.

A leaked key is only
part of the problem.

DeadBolt checks local files, staged changes, git history and container layers for leaked credentials and risky MCP or agent settings. Deterministic rules estimate potential authority and help a human prioritize what to review.

The offline core requires no API key or AI model. Run it from a Mac or Linux terminal, use the pre-commit hook, or add the published GitHub Action to a workflow.

Proposals, with people in control.

Text, JSON and SARIF reports connect findings to content-hashed remediation proposals. DeadBolt records human decisions in a hash-chained ledger and never uses discovered credentials or executes a fix.

Published v0.1.0 release and Marketplace Action. The synthetic demo produces 30 findings. Sixty automated tests and Linux CI across Python 3.10–3.13 cover detection, redaction, staged scans and approval integrity.

View Marketplace ActionRun the Mac/Linux demoRead the evidence brief

Authority is estimated; effective access remains unknown. Detection has finite rule coverage. Approver names are operator labels, and detecting a completely rewritten ledger requires a separately trusted head. The local AI model is optional; real-model inference remains unverified.

FEATURED / SIGNALDESK · OPENAI + SALESFORCE

Evidence before outreach.

Company research becomes a reviewable decision—not automatic permission to act.

Research the opportunity.
Earn the right to act.

SignalDesk connects OpenAI-powered company discovery, source-linked candidates and a human review queue. Exact-draft approvals, persistent Do Not Contact suppression and explicit research limits keep the workflow bounded.

The Salesforce GET-only preview adds a separate, read-only enterprise integration boundary. The XERJ team selected that implementation for its public code-reference corpus.

A system that knows when to stop.

In the documented workflow, a person approved an acquisition handoff. Separately triggered research could not verify the contact, so SignalDesk retained Needs evidence instead of producing an approvable message.

In the developer-org Salesforce run, two synthetic Leads produced one blocked and one requiring review. Lead permission metadata reported query access allowed and create/update/delete denied. The preview made no CRM writes and granted no outreach authority.
